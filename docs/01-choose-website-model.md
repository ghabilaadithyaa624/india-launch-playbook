# 01 · Choose the right website model

The fastest way to overspend is to build a platform when a sales website would validate the idea. Choose the smallest model that can prove the next business assumption.

| Model | Use it to prove | Typical first release |
|---|---|---|
| Brochure / portfolio | Credibility and service enquiry | 5–8 pages, contact form, analytics |
| Landing page | Demand for one offer | Single page, lead capture, calendar |
| Content / blog | Audience and search demand | CMS, publishing workflow, newsletter |
| E-commerce | Repeatable product sales | Catalog, cart, checkout, fulfilment |
| SaaS | A recurring software workflow | Accounts, core job, billing, support |
| Marketplace | Two-sided matching | Supply onboarding, demand request, matching |
| Real-time application | Time-sensitive coordination | Status updates, notifications, audit trail |
| PWA | Mobile-first web usage | Install prompt, responsive UI, resilient loading |

## A useful rule

If a human can complete the service manually for the first 20 customers, do that before automating the edge cases. A prototype is not a failed platform; it is evidence about what your platform must eventually do.

> **For logistics or service marketplaces**
> Start with supply verification, one request flow, one matching method, clear status updates and a human escalation path. Live maps, automatic pricing, wallet balances and complex ratings can follow after you have repeat usage.
